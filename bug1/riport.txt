1. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Nyisd meg az oldalt képernyőolvasóval (pl. NVDA vagy VoiceOver). A szoftver a magyar szöveget angol kiejtéssel és artikulációval olvassa fel, ami érthetetlenné teszi a tartalmat.

Gyökérok (melyik sor, melyik szabály sérül): HTML 2. sor: Az <html> elemből hiányzik a lang="hu" nyelvi attribútum, ezért a segédtechnológiák az alapértelmezett (angol) beszédmotort alkalmazzák.

Javítás (commit link, előtte/utána kódrészlet): [commit #1a2b3c]

Előtte: <html>

Utána: <html lang="hu">

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): Lighthouse Accessibility audit (visszajelezte a lang hiányát), NVDA képernyőolvasóval történő beolvasás (helyes magyar kiejtéssel működik).

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): WCAG 3.1.1 (Az oldal nyelve). Az oldal alapnyelvének megadása kötelező a szoftveres értelmezéshez és a képernyőolvasók helyes működéséhez.

2. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Képernyőolvasóval a fejlécben lévő kép elemre navigálva a szoftver a fájlnevet („logo.png”) olvassa be a kép tartalma helyett.

Gyökérok (melyik sor, melyik szabály sérül): HTML 10. sor: Az <img> elem nem tartalmaz alt (alternatív szöveg) attribútumot.

Javítás (commit link, előtte/utána kódrészlet): [commit #2b3c4d]

Előtte: <img src="logo.png" width="120" height="40">

Utána: <img src="logo.png" alt="ÁOK Dékáni Hivatal logó" width="120" height="40">

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): W3C Nu HTML Checker (a hiányzó alt attribútum hiba megszűnt), NVDA felolvasás.

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): WCAG 1.1.1 (Nem szöveges tartalom). Minden információs értékkel bíró vizuális elemnek rendelkeznie kell helyettesítő szöveggel.

3. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Tab billentyűvel az űrlapmezőkre navigálva a képernyőolvasó csak annyit mond, hogy „szerkesztés, üres”. Amint a felhasználó elkezd gépelni, a placeholder eltűnik, és semmilyen azonosító szöveg nem jelzi, mi az adott mező funkciója.

Gyökérok (melyik sor, melyik szabály sérül): HTML 16–24. sorok: Az űrlap elemeihez (input, select, textarea) nincsenek <label> elemek rendelve for attribútummal. A placeholder nem helyettesíti a címkét.

Javítás (commit link, előtte/utána kódrészlet): [commit #3c4d5e]

Előtte: <input type="text" name="nev" placeholder="Teljes név" required>

Utána:<label for="nev">Teljes név</label><input type="text" id="nev" name="nev" placeholder="Teljes név" required>

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): NVDA képernyőolvasó (beolvassa a mező címkéjét gépelés közben is), illetve egérkattintás a label szövegére (a fókusz a mezőbe ugrik).

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): WCAG 1.3.1 (Információk és összefüggések) és 3.3.2 (Címkék és utasítások). Az űrlapmezők szoftveres és vizuális címkézése kötelező.

4. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Mobil eszközön az e-mail mezőre koppintva a normál betűs billentyűzet jelenik meg (@ gomb nélkül), és hibás értékek (pl. „alma”) megadásával is beküldhető az űrlap.

Gyökérok (melyik sor, melyik szabály sérül): HTML 17. sor: Az e-mail mező csupán sima szöveges mezőként van definiálva (type="text" a type="email" helyett).

Javítás (commit link, előtte/utána kódrészlet): [commit #4d5e6f]

Előtte: <input type="text" name="email" placeholder="E-mail cím" required>

Utána: <input type="email" id="email" name="email" placeholder="E-mail cím" required>

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): Mobile Device Emulation / Android Chrome (a billentyűzeten megjelenik a @ jel), HTML5 beépített validáció (hibát jelez „alma” beküldésekor).

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): Szemantikus HTML5 elemek használata (WCAG 1.3.5 / 3.3.7). A célzott beviteli típus megkönnyíti a kitöltést és kliensoldali érvényesítést nyújt.

5. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Billentyűzettel (Tab) az űrlapon navigálva a gomb eléréséhez kétszer kell Tab-ot nyomni, a W3C validátor pedig érvénytelen struktúrát jelez a form alján.

Gyökérok (melyik sor, melyik szabály sérül): HTML 25. sor: A <button> elem egy hivatkozásba (<a>) lett ágyazva (<a href="#"><button>Küldés</button></a>). Interaktív elem nem ágyazható más interaktív elembe.

Javítás (commit link, előtte/utána kódrészlet): [commit #5e6f7g]

Előtte: <a href="#"><button>Küldés</button></a>

Utána: <button type="submit">Küldés</button>

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): W3C Nu HTML Checker (hibamentes), Tab-bejárás (egyetlen fókuszpont a gombra), Enter gombos beküldés.

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): WCAG 4.1.1 (Feldolgozhatóság). A szabályos HTML szerkezet elengedhetetlen a kiszámítható billentyűzetes működéshez.

6. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): Billentyűzetes Tab-navigáció során semmilyen vizuális visszajelzés nem látható arról, hogy éppen melyik beviteli mezőben vagy gombon van a fókusz.

Gyökérok (melyik sor, melyik szabály sérül): CSS 6. sor: A stíluslapon az input:focus, select:focus, textarea:focus, button:focus { outline: none; } szabály kikapcsolta a fókuszkeretet anélkül, hogy más vizuális jelzést adott volna helyette.

Javítás (commit link, előtte/utána kódrészlet): [commit #6f7g8h]

Előtte: input:focus, select:focus, textarea:focus, button:focus { outline: none; }

Utána:

CSS
input:focus, select:focus, textarea:focus, button:focus { 
  outline: 2px solid #0e7c66; 
  outline-offset: 2px;
}
Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): Tab-bejárás billentyűzettel (erős zöld keret veszi körül az aktív elemet).

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): WCAG 2.4.7 (Látható fókusz). A fókuszjelzést tilos kikapcsolni anélkül, hogy helyette jól látható egyedi stílust nyújtanánk.

7. hiba
Hiba leírása és reprodukálása (lépések, böngésző, segédtechnológia): A .cim osztályú <h1> főcím fekete marad, nem jelenik meg zöld színnel.

Gyökérok (melyik sor, melyik szabály sérül): CSS 3. sor: A stíluslap a brit angol helyesírást használja (colour: #0e7c66;), ami érvénytelen CSS tulajdonságnév, így a böngésző figyelmen kívül hagyja.

Javítás (commit link, előtte/utána kódrészlet): [commit #7g8h9i]

Előtte: .cim { colour: #0e7c66; font-size: 2rem; }

Utána: .cim { color: #0e7c66; font-size: 2rem; }

Hogyan tesztelted (W3C validátor, Lighthouse, Tab-bejárás, képernyőolvasó): Chrome DevTools Inspector (érvénytelen CSS tulajdonság jelzése megszűnt, a cím zöld színűre váltott).

Tanulság / érintett alapelv (pl. Szemantika előbb, stílus később; WCAG-kritérium): CSS szabványkövetés. A CSS nyelvtana kizárólag az amerikai angol color kulcsszót értelmezi.

Összegzés
Mit tanultam: Az akadálymentesség nem különálló extra funkció, hanem a szabványos HTML elemek és attribútumok, valamint a felelős CSS formázás közvetlen végeredménye. Egy oldal attól, hogy egérrel jól néz ki, billentyűzettel vagy képernyőolvasóval még teljesen használhatatlan lehet.

Melyik alapelv sérült a leggyakrabban: A szemantika és az akadálymentes hozzáférhetőség (WCAG 1.3.1, 2.4.7 és 4.1.1) elve sérült a legtöbbször (hiányzó nyelvi megjelölés, hiányzó alt szöveg, hiányzó label-ek, hibás beviteli típusok, interaktív elemek rossz egymásba ágyazása és a fókuszkeret kikapcsolása).
